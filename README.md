# PeerVault

PeerVault is an offline-first, decentralized password manager that bridges your Android smartphone and desktop browsers through hyper-local LAN sync. 

Instead of relying on remote cloud servers to store your master passwords, PeerVault strictly secures your encrypted vault on your Android device. It uses the phone's native hardware biometrics (Fingerprint/Face Unlock) to authorize everyday password usage via real-time WebSocket requests to the browser extension, resulting in an unphishable, zero-trust password management architecture.

## 🚀 Key Features

* **Cloud-Free Architecture**: Your vault is purely localized to your hardware. No central servers, no cloud subscriptions, no remote databases. Syncing to desktop happens seamlessly over local Wi-Fi (mDNS).
* **Zero-Knowledge Hardware Gating**: The desktop browser extension never actually holds or caches your passwords in plaintext. Every time you autofill a form, reveal a password, or copy a credential, the extension live-pings your Android phone for cryptographic Biometric authorization.
* **Native Android OS Autofill**: Hooks natively into the Android OS Autofill Framework to supply passwords to any installed mobile app. Explicit Compatibility modes are injected to force autofill capability inside custom-rendered browsers like Chrome, Firefox, and Brave natively natively without extensions.
* **Complex Shadow DOM Piercing**: The Chromium extension is built with advanced UI heuristics designed to intelligently penetrate modern Web Component DOM isolation (Shadow Roots) commonly used in Single-Page Applications, ensuring login fields are reliably detected.
* **Seamless Local Import**: Painlessly import your existing browser passwords securely to your phone or extension. PeerVault natively parses complex CSV exports dynamically from Chrome, Brave, Edge, and Firefox.


## 🛠️ Tech Stack & Architecture

PeerVault consists of two primary components communicating over encrypted WebSockets:

1. **The Mobile Vault (`/app`)**: Built in **Flutter & Dart**, functioning as the cryptographic center. 
    - Implemented completely without fragile codegen (no Freezed or build_runner dependencies) for absolute cross-platform integrity and stability.
    - Backed by an atomic, write-through JSON store for simplified resilience.
    - Operates a headless Dart Background Isolate (`autofillMain`) to process dynamic Android Autofill OS requests without keeping the UI alive in memory.
2. **The Browser Extension (`/extension`)**: A modern **Manifest V3 Chromium Extension** built in **TypeScript**.
    - Integrates heavy cryptography (ECDH pairing, AES-GCM, HMAC-SHA256) seamlessly on the web layer to handshake directly with the phone.
    - Leverages modern Service Workers to throttle event lifecycles perfectly.

## 📦 Installation & Setup

### Prerequisites
* Flutter SDK (3.4.0+)
* Node.js & npm (for building the extension)
* An Android device and Desktop Computer connected to the same Local Area Network (Wi-Fi).

### 1. Building the Android App
The mobile app operates as the host server.
```bash
cd app
flutter pub get
# Connect your physical Android Device
flutter run --release
```
*Note: Make sure to navigate to Android Settings -> Passwords & Accounts -> Autofill Service, and select `PeerVault` to activate seamless OS autofill!*

### 2. Building the Browser Extension
```bash
cd extension
npm install
npm run build
```
1. Open up Google Chrome, Brave, or Edge.
2. Navigate to `chrome://extensions`.
3. Enable **Developer mode** in the top right.
4. Click **Load unpacked** and select the `/extension/dist` folder generated by the build.

### 3. Pairing
Click the PeerVault extension icon in your browser toolbar to get started. Open the PeerVault app on your phone, navigate to Devices, scan the QR code displayed in your browser, and your devices are now cryptographically paired!

## 🔐 Security Overview
PeerVault encrypts passwords using standard AES-GCM logic. When syncing, devices perform a P-256 ECDH Key Exchange over the local LAN. No passwords traverse the network without encryption, and cryptographic secrets are never transmitted externally.
